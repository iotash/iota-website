A release about what stays still on screen. **Typing `/` no longer moves the
conversation**: the completion list opens over its bottom rows instead of
pushing it up. **A conversation starts at the top of the screen** and grows
downward. **Every list marks its current row the same way**, and **a message
from another agent in herdr-core reads as a message**, under a `hc from:` tab.

<!-- truncate -->

## Changed

- **Typing a slash command no longer moves the conversation.** The
  completion list opens over the bottom of the conversation instead of
  pushing it up. Typing more letters shortens the list and uncovers what is
  behind it, with no empty rows between the list and its top line. The rule
  that separated the list from what you type now sits on top of the list, and
  one empty row separates the list from your input.
- **A conversation starts at the top of the screen.** A new session's banner,
  and the rounds a resumed session replays at startup, start at the top and
  the conversation grows downward, scrolling only once it fills the screen.
  A conversation short enough to fit above the completion list is never
  covered by it.
- **Every list marks its current row the same way.** The completion list,
  the pickers and the lists in `/model`, `/tools`, `/jobs`, `/session` and
  the rest shade the whole current row, put a `▸` in front of it and set its
  label in bold. Rows with coloured labels of their own (`/tools`, `/jobs`)
  used to get only the `▸`; they now get the full highlight. A checked item
  in a multi-select keeps its `[x]`, in bold green, beside the `▸`. With
  `NO_COLOR` the shading goes and the `▸` and the bold stay.
- **A sub-agent's message in herdr-core reads as a message.** Inside
  herdr-core, a message handed over as `<hc from="worker-2">…</hc>` shows
  only what is inside it in your block, with `hc from:worker-2` on a gray tab
  just above. Only herdr-core's own `hc` element is treated this way, and
  only inside herdr-core: XML you paste yourself, `<hc>` anywhere else
  included, is shown and sent exactly as you typed it. Inside herdr-core an
  `<hc>` you paste gets the tab too, but the model still receives exactly
  what you sent. A long message shows its first 20 lines under the tab, like
  any long paste. The tab line is part of your message on screen: you can
  select, copy and search it, and it is written out when iota exits.
- **rmcp is 3.9**, past a security advisory on the version iota used
  before. An MCP server that answers 429 now says the server is limiting
  requests, and a 429 or 5xx carries the server's `Retry-After` when it sends
  one; the page behind a 5xx is no longer read, so its title is not shown.

## Fixed

- **A resize that ends where it began no longer leaves a broken screen.**
  tmux can end a resize with the window back at its old size; iota saw no
  change and redrew only what it thought had moved, over a screen the
  terminal had cropped. Every resize now repaints the whole screen.
- **On Windows, a write outside the project is asked about again.** A path
  the system spelled `\\?\C:\…` was read as inside a project at `C:\…`, so
  the write was not asked about, and its result showed the path as
  `//?/C:/…`.
