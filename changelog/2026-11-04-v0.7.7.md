A release for image agents. **An image agent on Venice works in the chat
again** — every interactive turn used to fail — and **`/model` on an image
agent now lists image models** on Venice and OpenRouter, not their text
models or a dozen of them. A picture made in a chat that is not saved is no
longer thrown away after it was paid for, and a new `moderation: low` asks
an image model for less restrictive moderation.

<!-- truncate -->

## Added

- **Image models can ask for less restrictive moderation.** Set
  `moderation: low` on a model of a `type: images` provider, or turn on the
  Moderation switch in `/model`, and each generation asks for it. Venice
  reads the same setting and otherwise blurs adult content. Without the key
  nothing is sent and the provider's default (`auto`) stands. Edits of an
  existing picture do not carry it, and on any other provider type the key
  is ignored with a warning.

## Fixed

- **Image agents on Venice work in the interactive chat.** iota asks an
  image endpoint to stream a preview while the picture is drawn, and Venice
  refused that request with a 400, so every interactive turn on a
  `venice-image` agent failed. Such a refusal is now followed by one plain
  request without the preview. A 400 comes before anything is generated and
  is not billed, so this never pays for a second picture. Endpoints that do
  stream, such as OpenAI's, still show the preview.

- **`/model` on an image agent lists image models, on Venice and OpenRouter
  too.** iota now reads how an endpoint labels its models, keeps the image
  ones, and also asks the endpoint for them directly, because its plain list
  may leave them out: Venice shows its 43 image models instead of its text
  models, OpenRouter 63 instead of a dozen. An endpoint that labels nothing,
  such as OpenAI's or xAI's, still lists every model. When the labels mark no
  image model, the picker says so, and you can still type a model id.

- **A picture generated in an unsaved chat is kept.** With `no_save:` or
  `--no-save`, an interactive turn reported `$HOME is not defined` and
  dropped the picture after it was paid for. It now goes to
  `~/.iota/images`, where a `-m` run puts it.
