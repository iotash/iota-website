You can now tell at a glance that a turn is still going. **The status row
stays busy from the moment you send a message until the turn is over**, says
what the turn is doing, and keeps one clock for all of it. Which tool is
running, and for how long, stays on the tool's own line. And a tool call the
model writes more text after no longer runs with nothing on screen.

<!-- truncate -->

## Changed

- **The status row says the chat is busy for the whole turn.** Until v0.7.1
  the spinner showed only while iota waited for the model, and the row went
  blank once the reply started or a tool ran. Now one busy segment stays up
  from the moment you send a message until the turn is over, and names what
  the turn is doing: `Waiting for the model`, `Thinking`, `Responding`,
  `Running tools`, or `Compacting` when it compacts the context before
  sending.

  - **Its clock counts the whole turn**, not the phase: moving from
    `Responding` to `Running tools` changes the word, not the time. It stops
    while the turn waits for you to answer an approval or a question.
  - **Which tool is running, and for how long, is still on the tool's own
    line** above the input — the status row says only the phase.
  - **`(ESC to cancel)` appears only on the status row.**
  - **When the turn ends with a background job still running, the status row
    just shows the job**, without a spinner.

  A `shell` call running after its approval — the call's line above the
  input, the status row below it:

  ```text
  ⠼ [shell sleep 4; echo fg-done]
    ⎿ 2s
  ```

  ```text
    fake · ↑ 22 ↓ 14 · 0% / 128k · ⠼ Running tools  2s (ESC to cancel)
  ```

## Fixed

- **A tool call the model keeps talking after is shown while it runs.** When
  a model wrote more text after composing a tool call, the call could run
  with nothing on screen — its line appeared only once it had finished, its
  clock starting there — or under the placeholder it had while being written
  (`[write_file …]`) instead of its own header with its arguments.
