A release about one way to say what is allowed. **An agent's `allow:` and
`--allow` replace six older spellings**: `outside_writes:`, `write_roots:`,
`tools.code.auto_write`, `tools.shell.auto_run`, `mcp_servers.<name>.auto_run`
and `--add-dir`. A config that still sets one of the keys fails to load and
says what to write instead. Beside that, **any terminal that reads OSC 7501
shows iota's state**, and **iota knows it runs in rex**.

<!-- truncate -->

## Added

- **An agent's `allow:` says what it may do without asking.**
  `agents.<name>.allow: [~/scratch, shell, edit_file, "github:*"]` takes
  `/allow`'s targets — a directory, a built-in tool that asks,
  `<server>:<tool>` or `<server>:*` — for every run of that agent, `-m`
  included. A mistake fails the load naming the entry; a bare `/allow` lists
  the entries read-only and `/status` counts them.
- **`--allow <target>` allows the same for one run.** `iota run` and
  `iota resume` take it, repeatable, and a `--mcp` server by its whole value,
  so a `-m` run can finally call a `--mcp` server's tools. It replaces
  `--add-dir`: `--allow <dir>` does what it did.
- **`/allow ` lists what you can grant**: the built-in tools that would still
  ask and the connected MCP servers; Enter on a server shows `*` and its tools.
- **iota knows it runs in rex.** Inside a rex block the model is told
  `host: rex`, the block and the session, so it can drive rex beside itself
  (`rex split`, `rex capture`); the banner says `in rex`. See
  [Terminal hosts](/docs/hosts#rex).
- **Text in the composer can be selected.** A drag copies what it covers,
  double-click selects a word, triple-click the whole draft; typing replaces
  the selection.

## Changed

- **Any terminal that reads OSC 7501 now shows iota's state, not only
  herdr-core.** iota asks its terminal once at start-up; one that answers gets
  `working`, `blocked`, `idle` and `error` instead of the OSC 9;4 progress bar.
  Inside herdr or cmux the terminal is not asked. Inside herdr-core, a terminal
  that could not be asked now gets no report.
- **Commands iota runs inside herdr-core get `HC_TERMINAL_ID` again.** An
  `iota` they start stays off the chat's state through `IOTA_STATUS_SESSION`;
  the `hc note` line is gone from the model's environment.
- **`/allow` takes the scope last: `/allow <target> project`.** The old order
  is refused and says the line to type.
- **A bare `/allow` no longer browses for a directory**: type
  `/allow <dir>`. With nothing to list it prints a one-line hint.
- **Grants load silently** — no `grants: …` line; `/status` and the bare
  `/allow` panel list them.

## Removed

Each key below fails the load when a config still sets it, even to `false`,
and the error says what to do instead.

- **`outside_writes:`** — a write outside every root asks you, and a `-m` run
  refuses it; the error says to delete the key.
- **`write_roots:`** — list each directory in the agent's `allow:`, or pass
  `--allow <dir>` for one run.
- **`tools.code.auto_write`** — `allow: [edit_file, write_file]`.
- **`tools.shell.auto_run`** — `allow: [shell]`. A mistyped key under
  `tools.shell` or `tools.code` now fails the load too.
- **`mcp_servers.<name>.auto_run`** — `"<name>:*"` (or `"<name>:<tool>"`) in
  the `allow:` of each agent that may run its tools without asking.
- **`--add-dir`** — `--allow <dir>`.

## Fixed

- **A plain chat no longer has project grants.** Only an agent with
  `mode: agent` (or `bot`) has them, and never when its project root is your
  home directory or above it; a project grant made from a plain chat in 0.12.0
  no longer applies.
- **Two `shell` calls in one round are asked about one by one.** Without a
  sandbox they could go out together as a parallel batch and run unasked; a
  call that would be asked now never joins a batch.
- **A message from another process is held after any tool grant**, not only
  when a config switch said so.
- **A protected file written in another case is still protected**
  (`.IOTA.YAML`, `.GIT` on macOS and Windows).
- **Windows paths are directories** in `allow:`, `--allow` and `/allow` —
  `C:\out`, `C:/out`, `\\server\share`, `/out` — and a granted directory reads
  `C:\…`, not `\\?\C:\…`.
- **`/allow <server>:` no longer lists the server again**, and a `-m` run
  without a project no longer suggests a project grant.
